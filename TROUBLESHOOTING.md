# 🩺 TROUBLESHOOTING — известные проблемы и обходы

> Основано на реальных полевых отчётах + разборе кода раннера.
> Важно: **в раннере нет никаких фильтров вывода** — он отдаёт ровно то, что вернул процесс.
> Если вывод пустой/странный — смотри поля `executed`, `cwd`, `stdout_bytes`, `stderr_bytes` в результате: они добавлены именно для диагностики (v1.6.0).

## Как читать результат (формат v2.x)

```text
[LOCAL EXEC RESULT] seq=12 status=done runner=shell exit=0 executed=yes cwd="C:\...\server" stdout_bytes=123 stderr_bytes=0 dur=0.4s
$ <команда>
--- stdout ---
...
```

| Поле | Что значит |
|---|---|
| `exit` | код возврата (0 = ок; 124 = таймаут). Внимание: PowerShell при ненайденном пути часто даёт `exit=0` с ошибкой в stderr! |
| `seq` / `status` | сквозной номер запуска; `running` — выполняется, `done` — готов, `skipped` — пропуск (дубль/лимит/опасная), `error` — выполнить не удалось |
| `dur` | длительность выполнения (`3ms` / `1.2s`) |
| `executed` | `yes` — команда реально запускалась; `no` — отклонена до запуска (пустая, неверный раннер и т.п.) |
| `cwd` | папка, **в которой** выполнялась команда. Причина №1 «пустых» выводов — не та папка! |
| `stdout_bytes` / `stderr_bytes` | точные размеры вывода в байтах |
| `…(обрезано вставкой: лимит N симв.)` | сработала обрезка вставки в чат (по умолчанию 32000 симв., 0 = без лимита — настраивается в ⚙️) |
| `insert_truncated=yes shown_chars=X/Y` | то же в шапке: показано X из Y символов |
| `(…обрезаны сервером: лимит N байт)` | сработала обрезка сервера (по умолчанию 1 МБ, флаг --max-output, 0 = без лимита; оставляется НАЧАЛО вывода) |
| `(команда убита по таймауту…)` | превышен таймаут (`exit=124`, `timed_out`): вывод частичный, подробности — `[TIMEOUT]` в stderr |

## Проблемы и решения

### 1. Многострочный PowerShell (`if`/`foreach`) не выполняется
**Было:** скрипт уходил в `powershell -Command` одной строкой, конструкции ломались на парсинге, `exit=0` с пустым stdout.
**Исправлено в v1.6.0:** PowerShell выполняется через временный `.ps1`-файл (`-File`), многострочность работает нативно. Плюс флаги `-NonInteractive` (не виснет на вопросах) и `-ExecutionPolicy Bypass` (не упирается в политики).

### 2–3. `Get-Content` / `type файла` → пустой stdout
**Настоящая причина (гипотеза про «фильтры» неверна — их нет):** команда запускалась **не в той папке** (сервер стартует в `server/`, а файл лежит выше) → «cannot find path» уходил в **stderr**, а `exit` остался `0`, stdout пустой. Классика PowerShell: ненайденный путь — это non-terminating error, код возврата не меняется.
**Что делать:**
1. Смотри поле `cwd` в результате — та ли папка?
2. Читай `stderr` — там обычно и лежит ответ.
3. Используй абсолютные пути (ИИ теперь обязана узнать `pwd` первым делом — правило 7 промпта).
4. Если файл точно есть, а вывод пуст — пришли мне `cwd` + полный текст результата, будем копать.

### 4. Обрезка больших выводов «без объяснений»
**Так задумано, но теперь прозрачно:** лимиты — 1 МБ на сервере (флаг --max-output), 32000 символов при вставке в чат (поле в ⚙️); 0 = без лимита. С v1.6.0 в результате всегда есть пометка с конкретным лимитом. Для больших листингов проси ИИ дробить вывод (`Select -First N`, постранично).

### 5. Кириллица → `????` / кракозябры
**Причина:** консоль Windows (`cp866`) + декодирование вывода в локали.
**Исправлено в v1.6.0 (в большинстве случаев):** раннер забирает вывод байтами и декодирует по цепочке UTF-8 → CP866 → CP1251; `cmd` стартует с `chcp 65001`, PowerShell — с UTF-8 `OutputEncoding`, `.ps1` пишется с BOM.
**Запасной путь (безотказный):** base64 — `[Convert]::ToBase64String([System.IO.File]::ReadAllBytes("путь"))`, декодируй у себя.

### 6. Несколько команд в одном сообщении → путаница результатов
**Было:** автопанели запускались параллельно, вставки шли в порядке завершения, а не в порядке блоков.
**Исправлено в v1.6.0:** очередь автозапусков — строго по одному, сверху вниз; на панелях видно «В очереди (#2)…».

### 7. `uname -a; pwd` валится целиком на Windows
**Не баг раннера:** `;` — не разделитель в `cmd` (там `&`), `uname` на Windows нет. ИИ должна проверять ОС первым делом (правило 7 промпта) и писать `&` для cmd / `;` для PowerShell.

### 8. `$PSVersionTable.PSVersion` → странное число
**Не баг:** ИИ вызвала метод объекта и получила поле версии. Раннер отдал честный вывод PowerShell. Для строки версии: `$PSVersionTable.PSVersion.ToString()`… впрочем, ИИ уже в курсе 🙂

### 9. `Format-Table` жмёт колонки на длинных путях
**Поведение PowerShell** в узкой консоли без окна. Обход (уже в промпте): `| Format-Table -AutoSize` или `| Out-String -Width 200`.

### 10. Дубли `[LOCAL EXEC RESULT]`
**Был реальный баг:** ручной клик ▶ во время обратного отсчёта запускал команду второй раз, вставка дублировалась.
**Исправлено в v1.6.0:** защита от повторного запуска (`running`-флаг) + очередь.

### 11. Непонятно, запускалась ли команда вообще
**Исправлено в v1.6.0:** поле `executed=yes/no` + `stdout_bytes`/`stderr_bytes` в каждом результате.

### 12. Хочется «сырой» вывод (base64-режим раннера)
**Не реализовано** (и не планируется в ближайшее время — умный декод v1.6.0 закрывает 95% случаев). Обход: `[Convert]::ToBase64String(...)` со стороны ИИ — работает безотказно.

### 13. Приходят старые/повторные результаты
**Исправлено в v2.0.0:** дедуп автозапусков — одинаковая команда в одной среде не выполняется повторно в течение 60 секунд (панели-дубли от перерисовки чата отсекаются, в чат идёт `status=skipped reason=duplicate`). Плюс каждый результат нумеруется (`seq=N`) — сверяйся по номеру. Ручной запуск кнопкой ▶ дедуп не трогает.

### 14. Быстрые команды склеивались в одно сообщение
**Исправлено в v2.0.0:** очередь ждёт конца автоотправки, прежде чем брать следующую команду. Один результат = одно сообщение, порядок = порядок выполнения.

### 15. cwd = C:\Windows\System32
**Исправлено в v2.0.0:** если сервер запущен из системной папки (System32/SysWOW64/Windows), он сам переходит в домашнюю папку пользователя. Плюс два способа задать папку явно: флаг `python server.py --cwd D:\projects` и настройка «Рабочая папка» в ⚙️ (действует на все команды).

### 16. Эмодзи/кириллица в выводе python едут в ????
**Исправлено в v2.0.0:** python-раннер запускается с `PYTHONUTF8=1`, вывод всегда UTF-8. Если мусор остался в shell/powershell — обход: `chcp 65001` в начале команды.

### 17. Автопилот не срабатывает (есть кнопка «✋ Отмена авто», но запуска нет)
**Был реальный баг (v1.9.0–v2.0.0):** проверка «панель в DOM?» стояла в постановке в очередь, а старт происходил до вставки панели — очередь молча отбрасывала запуск.
**Исправлено в v2.0.1:** проверка переехала в насос очереди + claimed-флаги от двойных запусков + страховки от зависания очереди. Обнови расширение.

### 18. Ложные панели EXECUTE? на обычных блоках
**Был реальный баг:** слово «EXECUTE» в тексте соседней панели принималось за метку — обычный блок после execute-блока получал лишнюю панель.
**Исправлено в v2.1.0:** свои панели пропускаются при поиске. Плюс честные пометки таймаута (`timed_out`), обрезка сервера в байтах с начала, `~` в путях, защита от гигантских тел запросов.

### 19. Автопилот выполняет старые команды после обновления/F5
**Был реальный баг:** вся история чата воспринималась как новые блоки и прогонялась заново.
**Исправлено в v2.2.0:** список выполненных (до 200, переживает перезагрузки) — повтор из прошлой сессии пропускается с запиской `status=skipped reason=already-executed`; блоки, уже бывшие на странице при загрузке, тоже пропускаются (`reason=old-block`). Повтор — вручную кнопкой ▶. Очистить список: ⚙️ → Автопилот → «🗑 Очистить историю».

### 20. python/PowerShell-код выполняется в cmd (runner=shell)
**Причина:** ИИ написал простой ` ```execute ` вместо ` ```execute-python `/` ```execute-pwsh ` (или сайт отрезал суффикс языка) — расширение честно выполнило в shell.
**Исправлено в v2.3.0:** сниффер содержимого — простой execute-блок с очевидным кодом (`import`/`print(`/`def` → python; `New-Item`/`Get-` → powershell; `console.log`/`require` → node) выполняется в правильной среде сам; среда видна в селекте на панели. Плюс промпт для ИИ теперь требует выбирать язык блока строго по содержимому (обнови промпт в чате из `SYSTEM_PROMPT.md` или кнопкой «📋 Скопировать промпт»).

### 22. Add-Type и часть PowerShell-скриптов уходят в cmd
**Был баг в сниффере v2.3.0–v2.3.1:** в списке глаголов PowerShell не хватало Add, Format, ConvertTo/From, Push/Pop и др.; скрипты с param(...), $var = ... и function Глагол-Существительное тоже не опознавались. Плюс память среды цементировала shell даже при простом подтверждении без смены селекта.
**Исправлено в v2.3.2:** список расширен, блочные комментарии <#...#> и /*...*/ перед кодом пропускаются; модалка пишет в память только явную смену среды, старые отравленные записи чистятся сами. Обнови расширение.

### 23. Общий аудит и устранение ошибок во всех модулях
**Исправлено в v2.4.1:**
- **Сниффер языков:** распознавание `async def` и `if __name__ == '__main__':` в Python; деструктурирующий `const { ... } = require(...)` и `let/var` в Node; `$env:...`, `[Console]::...`, `[System...]` и `$PSVersionTable` в PowerShell; поддержка кода на строке закрытия многострочных комментариев `<#...#>` и `/*...*/`.
- **Маркеры первой строки:** поддержка `# execute-python`, `// execute-js` и др. в начале блока с корректным вырезанием из тела команды.
- **Защита от повторного внедрения:** скрипт не дублирует MutationObserver, таймеры и обработчики сообщений при повторной инъекции.
- **Безопасность:** произвольные выделенные команды (`runArbitrary`) теперь ВСЕГДА требуют подтверждения, если команда опасная, даже если общий запрос подтверждения отключён.
- **Автоотправка в чат:** поиск кнопки отправки адаптирован под русскую локаль (`aria-label="Отправить..."`) и нестандартные элементы (`role="button"` в DeepSeek/Claude); генерация пары keydown + keyup для гарантированного срабатывания Enter.
- **Буфер обмена:** фоллбек на `document.execCommand('copy')` при запрете Focus в `navigator.clipboard`.
- **Автопилот:** сброс блокировки зацикливания при ручном перезапуске или включении автопилота; сохранение настроек по клавише Enter в попапе и окне настроек.
- **Тёмная тема:** правильное отображение модального окна и выпадающих списков сред в тёмном режиме.
- **Сервер:** поддержка IPv6 `[::1]`, расширений Firefox `moz-extension`, нормализация путей и пробелов в `cwd`.

## Быстрые обходы (шпаргалка для ИИ)

- 📖 **Чтение файлов:** абсолютные пути; если кракозябры — `[System.IO.File]::ReadAllBytes` + base64/hex.
- 🔤 **Кириллица:** обычно уже ок; нет — base64.
- 🗂 **Листинги:** `Get-ChildItem | Sort Length | Select -First N | Format-Table -AutoSize`.
- 📏 **Большие файлы:** кусками (первые N строк/байт), потом следующие.
- 🧩 **Сложная логика:** `execute-python` вместо однострочников `python -c`.
