# v2.10.5 — HTTP-транспорт для MCP + каталог серверов

## Добавлено

**Streamable HTTP для MCP-серверов.** Раньше поддерживался только `stdio` — локальный процесс. Из-за этого половина популярных серверов просто не запускалась: Context7, Notion, Zapier, Atlassian существуют только как удалённые HTTP-эндпоинты, ставить их не нужно.

Что учтено в реализации:
- ответ приходит и обычным JSON, и потоком `text/event-stream` — разбираются оба;
- сессия `Mcp-Session-Id` запоминается при `initialize` и возвращается в следующих запросах;
- уведомления (без `id`) ждут `202 Accepted` с пустым телом — ответного сообщения там нет;
- `Content-Type`, `Accept` и `Host` из конфига перезаписать нельзя: это сломало бы сам обмен. Токен в `Authorization` — можно;
- на `401/403` расширение прямо говорит, что нужен токен, а не «что-то пошло не так».

Интерфейс HTTP-клиента совпадает с stdio-клиентом, поэтому реестр, эндпоинты и UI о транспорте ничего не знают. В UI у сервера теперь видно `transport` и `url` — раньше HTTP-сервер выглядел бы «пустым», без команды.

## Каталог серверов — без добавления в конфиг

**[docs/mcp-servers.md](docs/mcp-servers.md)** — готовые записи для всех пяти групп из запроса: файлы и кодинг, веб-поиск и документация, память проекта, браузер и тестирование, интеграции. С указанием, что нужно ставить, какие ключи и где их взять.

**В `server/mcp_servers.json` они не добавлены** — по прямому требованию. Причина прагматичная: конфиг читается при каждом старте сервера, и прописанные там серверы означали бы, что расширение молча поднимает процессы и ходит в интернет у того, кто этого не просил.

Теперь это зафиксировано тестом: `ShippedConfigTests` проверяет **закоммиченную** версию конфига и падает, если там появится сервер из каталога или хотя бы один HTTP-адрес. Проверяется именно git-версия, а не рабочая копия — локально ты включаешь серверы сам, это твоё решение, и тест не должен за него ругать.

Попутно обновлён комментарий в самом конфиге: там было написано «Поддерживается только stdio-транспорт», что после этого изменения неправда.

## Чего поддержка не даёт

- **OAuth-логин не реализован.** Zapier, Notion, Atlassian требуют браузерного OAuth — пройти его нельзя. Работают только те, кому хватает статического токена в заголовке. Для Atlassian дан обходной путь через `mcp-remote`.
- **Устаревший «голый» SSE** (`GET` + события) не поддерживается.

Оба ограничения описаны в каталоге, чтобы не было сюрпризов при включении.
