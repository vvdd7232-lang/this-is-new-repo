# v2.10.3 — кнопки «Список инструментов для ИИ» снова видны

## Исправлено

- **Кнопок «Скопировать список для ИИ» и «Сохранить на рабочий стол» не было видно.** Они находились внутри блока `#mcpBox`, который скрыт переключателем «Включить MCP», а `mcpEnabled` по умолчанию выключен. То есть при выключенном MCP кнопок не было на странице вообще — хотя их `id` в разметке присутствовал.

- **Кнопка молча ничего не делала.** Даже если показать её принудительно, обработчик начинался с `if (!updateMcpBox()) return;` — при выключенном MCP нажатие не делало ничего, без единого сообщения об ошибке.

Блок вынесен из `#mcpBox` отдельным полем **«Список инструментов для ИИ»** с пояснением, зачем он нужен: модель не знает имён инструментов MCP и выдумывает их, поэтому отчёт с точными именами и готовыми блоками `execute-mcp` требуется вне зависимости от того, включён MCP или нет. Проверка `updateMcpBox()` из `mcpReport()` убрана — это справочник для модели, а не вызов инструмента.

## Почему это не поймали тесты

Прежняя проверка смотрела только на наличие `id="mcpReport"` в разметке. Кнопка там была — просто внутри скрываемого блока. Теперь проверка ищет закрывающий тег `#mcpBox` и требует, чтобы кнопка была **после** него, а также запрещает возврат проверки `updateMcpBox` в `mcpReport`.

## Проверки

- Живая проверка при `mcpEnabled=false`: обе кнопки видимы, уходят запросы `AX_MCP_REPORT` с `save=false` и `save=true`, статус отображается
- 399 JS-проверок, 102 Python-теста (кроме локально изменённого `mcp_servers.json` — см. ниже)

## Замечание про релизный конфиг

Сборка `server.zip` использует ваш локальный `server/mcp_servers.json`. Если в нём включены серверы (`enabled: true`), они попадут в архив — и у всех, кто скачает релиз, сервер попытается запустить эти процессы (скачать и выполнить сторонние пакеты). Перед публикацией этого релиза архив собран с выключенными серверами. Локальный файл не изменялся.
