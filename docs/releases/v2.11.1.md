# v2.11.1 — кото-тема и надёжный автопилот

Патч-релиз: починена кото-тема (она не работала внутри панели) и закрыты четыре дефекта автопилота, из-за которых команды могли выполняться повторно или панель переставала реагировать.

## Кото-тема: починка и аккуратность

- **Ушки, лапки и хвостик не появлялись на панели.** CSS использовал только селекторы светлого DOM (`[data-ax-cat="on"] .ax-btn`), а панель и модалка живут в закрытом shadow root — атрибут стоит на самом хосте, и правила до кнопок не доходили. Каждый селектор темы теперь продублирован для тени: `[data-ax-cat="on"] …` и `:host([data-ax-cat="on"]) …`.
- **Галочка в настройках ничего не делала.** `catMode` не читался из профиля оформления и не применялся к странице: `readUiTuning()` теперь его возвращает, `applyUiTuningToHtml()` ставит/снимает `data-ax-cat` на `<html>`, а на чекбокс повешен обработчик `change`.
- **Ушки «Выполнить» пропадали.** `:not(.ax-btn-icon)` поднял специфичность базовых правил выше override для кнопки запуска — ушки были невидимы (`opacity: 0`). Override-правила выровнены по специфичности.
- Ушки оставлены только на текстовых кнопках (иконочные — чистые), лапки панели заведены внутрь скругления, хвостик модалки и «усы» приведены в порядок; вся анимация уважает `prefers-reduced-motion`.

## Автопилот: четыре дефекта

- **Повторный запуск уже выполненного.** `applyPendingAuto()` вызывала `retry()` для *всех* живых панелей, включая завершённые. При смене настройки (включение автопилота, лимит вкладок) это могло заново отправить давно отработавшую команду: дедуп по сессии (`historyAge`) возвращает 0, а окно `dupAge` — всего 60 секунд. Теперь берутся только панели, которые ещё ни разу не стартовали (`done`/`started`/`claimed` пропускаются).
- **Панель не показывала очередь после повтора.** `retry()` не сбрасывал внутреннюю фазовую защёлку `phase2`, из-за чего `showQueued()` выходил сразу и статус «в очереди» не отображался за другой активной панелью. Флаг сбрасывается в `retry()`.
- **Ошибка не помечала панель завершённой.** `autoHandle.finish()` вызывался только в ветке успеха, поэтому после ошибки или блокировки whitelist флаг `done` оставался `false`, и панель снова попадала под `applyPendingAuto()`/`retry()` — упавшая команда запускалась повторно. Теперь `finish()` вызывается при любом исходе.
- **Панель, заблокированная на скане, не стартовала.** `startAuto()` выставлял `started = true` до проверок, поэтому панель, пойманная при `loopBlocked` или при выключенном автозапуске, навсегда теряла возможность стартовать позже. Флаг ставится только после успешной проверки всех условий.
