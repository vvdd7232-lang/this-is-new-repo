# ⚡ AI Execute Runner — ИИ из браузера выполняет команды на твоём ПК

Аналог **Claude Code / Codex**, но прямо в обычных чатах **ChatGPT**, **Claude**, **Arena** и **Google AI Mode** (а также Gemini, Copilot, Grok, DeepSeek и др.):

1. ИИ пишет команду в блоке ```` ```execute ````
2. Под блоком появляется кнопка **▶ Выполнить**
3. Ты подтверждаешь → команда выполняется **на твоём ПК**
4. Вывод вставляется обратно в чат кнопкой **📥 В чат** → ИИ продолжает работу

```
┌─ ChatGPT / Claude ─────┐   ┌─ Расширение ────┐   ┌─ Твой ПК ─────────┐
│ ```execute              │──▶│ Кнопка ▶ +      │──▶│ server.py         │
│ ls -la                 │   │ подтверждение   │   │ 127.0.0.1:8765    │
│ ```                    │◀──│ Вывод + вставка │◀──│ sh·py·node·pwsh   │
└────────────────────────┘   └─────────────────┘   └───────────────────┘
```

> ⚠️ **Почему две части?** Расширение браузера **не может** само запускать программы на ПК (это запрещено безопасностью браузеров). Поэтому нужен маленький локальный сервер `server.py` — он и выполняет команды. Это стандартная схема (так работают Claude Code, Multimodal и др.).

## 🚀 Установка за 5 минут

### Шаг 0. Скачай проект

- **Простой вариант:** зелёная кнопка **Code** → **Download ZIP** → распакуй архив.
- **Через git:** скопируй ссылку из той же кнопки **Code** и выполни `git clone <ссылка>`.

### Шаг 1. Запусти локальный сервер

Нужен **Python 3.8+** (обычно уже есть; проверить: `python --version`).

```bash
cd server
python server.py
# Windows:  py server.py
```

Должно появиться:

```
AI Execute Runner — локальный сервер запущен
http://127.0.0.1:8765
```

✅ Проверь в браузере: открой http://127.0.0.1:8765/ping — должен вернуться JSON `{"status": "ok", ...}`.

Флаги сервера: `python server.py --port 9999 --cwd D:\projects --max-output 0` — свой порт, рабочая папка для команд, лимит вывода (0 = без лимита). Если запустить из системной папки (System32) — сервер сам перейдёт в домашнюю. Рабочую папку можно задать и в расширении: ⚙️ → «Рабочая папка».

### ⚡ Настройка в один клик

Сервер при старте печатает готовую ссылку вида
`chrome-extension://<ID расширения>/options.html#ax-setup=…`, внутри которой адрес сервера и токен.
Скопируй её в адресную строку браузера — расширение само подставит адрес и токен и сразу проверит связь.
Токен при этом вычищается из адресной строки и хранится только локально.

> Это убирает самую частую проблему первого запуска: «бейдж offline» и `401 invalid token` из-за незаполненного токена.
> ID расширения виден в `chrome://extensions` (Chrome) или `about:debugging` (Firefox).

### Whitelist (защита от неразрешённых команд)

```bash
python server.py --whitelist whitelist.txt
```

Включает режим, когда выполняются **только** команды из указанного файла (по префиксу).
Если файла нет — он создаётся с дефолтным списком (только чтение: ls, cat, git status, python и т.п.).

**Что блокируется:**

- Команды не из списка -> HTTP 400 с blocked: true
- Цепочки и пайпы (`;`, `&&`, `|`, `$()`, `<`, `>`, обратные кавычки) -> HTTP 400, даже если первая команда разрешена
- Переводы строк тоже блокируются: многострочный текст выполняется построчно, поэтому `cd .` + `rm -rf /` — это обход, а не одна команда
- `view` подчиняется whitelist-режиму так же, как обычные команды (он читает файлы с диска)

**Что НЕ блокируется:**

- Ручной запуск кнопкой в чате — там ты видишь команду и подтверждаешь сам

**Формат файла:** одна команда/префикс на строку. Строки с # — комментарии.
Команда разрешена, если она равна префиксу или начинается с префикс + пробел:

- ls разрешит ls, ls -la, ls /tmp, но **не** lsfoo
- git status разрешит git status, git status -s, но не git push

**Зачем это нужно:** если автопилот вдруг сгенерирует что-то странное (или кто-то дёрнет /run в обход расширения) — сервер откажет. Это не замена ручному подтверждению, а дополнительный слой для автоматического режима.

### 🤖 MCP: Godot, Blender и другие MCP-серверы (экспериментально)

> ⚠️ **Экспериментальная функция, выключена по умолчанию.** Включается в двух местах: флагом `--mcp` на сервере и галочкой в настройках расширения. Ничего не работает, пока не сделано и то, и другое.

Подключает внешние MCP-серверы, чтобы ИИ в чате мог пользоваться их инструментами (создать объект в Blender, управлять сценой в Godot, читать файлы и т.п.).

**Почему это делает сервер, а не расширение.** MCP-серверы работают через stdio — это отдельные процессы, которые говорят JSON-RPC через stdin/stdout. Браузер запускать процессы не умеет в принципе, поэтому посредником служит `server.py`: он поднимает MCP-серверы как subprocess и отдаёт расширению только HTTP.

**Шаг 1. Опиши серверы** в `server/mcp_servers.json`:

```json
{
  "servers": [
    { "name": "blender", "command": "uvx", "args": ["blender-mcp"], "enabled": true },
    { "name": "godot",   "command": "npx", "args": ["-y", "godot-mcp"], "enabled": true }
  ]
}
```

Из коробки всё выключено (`enabled: false`) — включай то, что реально поставил.

**Шаг 2. Запусти сервер с MCP** — сервер спросит при старте:

```bash
python server.py
#   MCP [экспериментально] — внешние MCP-серверы (Godot, Blender и др.)
#   конфиг: ...\server\mcp_servers.json
#   Активные серверы: blender, godot
#   Включить MCP? [y/N]
```

Ответь `y` (подойдёт и «да»). Просто Enter = «нет» — по умолчанию ничего не включается.

Без вопроса (для ярлыков, автозапуска и скриптов):

```bash
python server.py --yes      # включить MCP
python server.py --mcp      # то же, явный флаг
python server.py --no-mcp   # не спрашивать и не включать
```

> Без терминала (ярлык, автозагрузка, CI) вопрос не задаётся и MCP остаётся выключенным — сервер не может зависнуть на `input()`. Для ярлыка с MCP добавь `--yes` в аргументы.
> Выбор действует только на текущий запуск: `server/mcp_servers.json` сервер не переписывает.

**Шаг 3. Включи галочку** ⚙️ Настройки → раздел **«Экспериментальное»** → «Включить MCP в расширении», затем «Сохранить всё». Кнопка «Проверить серверы» покажет список серверов и найденных инструментов.

**Шаг 4. Научи ИИ** — скопируй промпт кнопкой в разделе «Промпт для ИИ» и вставь его в чат.

**Шаг 5. Дай ИИ список инструментов.** Без него модель выдумывает имена вроде `blender.create_scene` — и вызов падает. В разделе **«Экспериментальное»** есть две кнопки:

- **«Скопировать список для ИИ»** — отчёт уходит в буфер обмена. Вставь его в чат вторым сообщением.
- **«Сохранить на рабочий стол»** — тот же отчёт ляжет файлом `mcp-tools.md` на рабочий стол: приложи его как контекст или открой и вставь.

По каждому инструменту отчёт содержит точное имя, описание, аргументы с типами и готовый блок `execute-mcp` с примером — останется подставить значения:

````
```execute-mcp
{"server": "blender", "tool": "create_cube", "arguments": {"size": 2}}
```
````

Имя сервера — из `server/mcp_servers.local.json`, `tool` — точное имя инструмента из отчёта.

Все нестабильные и новые функции живут именно в разделе «Экспериментальное» — со временем они могут переехать в обычные разделы или исчезнуть.

**Ограничения (почему это пока экспериментально):**

- только **stdio**: MCP-серверы запускаются как локальные процессы; HTTP/Streamable-HTTP транспорт не поддерживается
- требуется перезапуск/перечитывание конфига сервера, если ты его правишь («Перечитать конфиг» делает это без перезапуска)
- личные серверы описываются в `server/mcp_servers.local.json` (в `.gitignore`), шаблон `mcp_servers.json` остаётся выключенным

**Как MCP защищён:**

- каждый вызов проходит ту же проверку токена, Origin и `127.0.0.1`, что и обычные команды
- **в режиме whitelist MCP отключается целиком** (HTTP 403): whitelist проверяет shell-команды, а `tools/call` — нет, поэтому оставлять его включённым означало бы дыру. Если нужен MCP — запускай сервер без `--whitelist`
- опасные инструменты (`execute_*`, `run_code`, `write_*`, `delete_*`, `export_*`) **требуют подтверждения даже при автопилоте** — они исполняют код или меняют проект
- таймаут вызова ограничен 10 минутами, ответ обрезается тем же лимитом, что и вывод shell-команды, ключи `__proto__` в аргументах отклоняются
- токен доступа не покидает `background.js`: маскирование команд и вывода делает он, поэтому секрет не лежит в памяти страниц чата

> Сервер слушает **только 127.0.0.1** — доступен лишь с твоего ПК, из интернета к нему не достучаться.

### Шаг 2. Установи расширение в Firefox (основной браузер)

**Способ 1 (через распакованную папку — рекомендуется при разработке):**
1. Распакуй архив проекта `ai-execute-extension.zip` (если скачивал zip)
2. В Firefox открой адрес: `about:debugging#/runtime/this-firefox`
3. Нажми кнопку **«Загрузить временное дополнение…»** (Load Temporary Add-on…)
4. Зайди в папку **`extension/`** и выбери файл **`manifest.json`**!
   *(⚠️ Важно: выбирай именно файл `manifest.json` внутри папки `extension`, а не общий архив проекта — в архиве проекта `manifest.json` лежит не в корне, поэтому Firefox ругается «does not contain a valid manifest»).*

**Способ 2 (в 1 клик без распаковки):**
- В репозитории есть готовый файл **`firefox-addon.xpi`** (где `manifest.json` лежит прямо в корне архива) — в окне выбора файла можно сразу нажать на `firefox-addon.xpi`!

> 💡 **Для Chrome / Edge:** в папке `extension/` лежит готовый `manifest.chrome.json`. Чтобы запустить в Chrome, замени `manifest.json`:
> ```bash
> cp extension/manifest.chrome.json extension/manifest.json
> ```
> И загрузи распакованное расширение через `chrome://extensions` (включив «Режим разработчика»).

Открой файл **`SYSTEM_PROMPT.md`**, скопируй **короткий промпт** и отправь первым сообщением в чат. (Промпт есть и в попапе расширения — кнопка «📋 Скопировать промпт для ИИ».)

## 🧩 Какие блоки выполняются

| Блок | Что делает |
|---|---|
| ```` ```execute ```` / ```` ```exec ```` | shell-команда (`bash` на Mac/Linux, `cmd` на Windows) |
| ```` ```execute-python ```` | python-скрипт (тем же Python, что запустил сервер) |
| ```` ```execute-js ```` | Node.js-скрипт (нужен установленный `node`) |
| ```` ```execute-pwsh ```` | PowerShell (Windows) |
| ```` ```execute ```` (команда `view `) | просмотр изображения: `view C:\path\pic.png` |

Обычные ```` ```bash ```` / ```` ```python ```` **игнорируются** — это защита, чтобы примеры «для справки» случайно не запускались.

> 🔍 Даже если ИИ забыл суффикс: простой `execute` с очевидным python/PowerShell/JS-кодом выполнится в правильной среде (сниффер содержимого) — среда видна в селекте на панели.

### 🖼 Просмотр изображений — команда `view`

Чтобы ИИ (или ты) увидел картинку — скриншот, схему, диаграмму — используй команду `view`:

```````execute
view C:\Users\me\screenshot.png
```
````

Что происходит:

- сервер читает файл, проверяет что это изображение (по расширению + MIME) и возвращает как `data:` URL
- расширение показывает **превью прямо под панелью** — можно кликнуть и открыть в новой вкладке
- картинка **вставляется в поле ввода** через скрытый `input[type=file]` композера (DeepSeek, ChatGPT, Claude) либо через paste-событие, если чат — contenteditable с обработчиком вставки (Arena, Claude)
- если чат не принял файл автоматически — расширение честно об этом сообщает, а под превью появляется кнопка **🖼 Вставить в чат** для повтора
- вставляется самое нижнее поле ввода на странице; если ты уже печатаешь в поле — вставка идёт именно в него

Поддерживаются: `png`, `jpg`, `jpeg`, `gif`, `webp`, `bmp`, `svg`, `ico`, `avif` — до **10 MB**.

Путь может быть абсолютным или относительным к рабочей папке сервера.

> 🩺 Картинка не вставилась? Открой F12 на странице чата и выполни `__axDiag()` — покажет, какое поле ввода найдено, есть ли у чата скрытый `input[type=file]` и что доступно из API. Подробности в [TROUBLESHOOTING.md](TROUBLESHOOTING.md).

## 📋 Список инструментов для ИИ + защита MCP (v2.9.0)

### 📋 Отчёт по инструментам
Модель не знает имён инструментов MCP и выдумывает их — вызов падает. Теперь в разделе
**«Экспериментальное»** есть две кнопки:

- **«Скопировать список для ИИ»** — отчёт в буфер обмена, вставляешь в чат вторым сообщением
- **«Сохранить на рабочий стол»** — файл `mcp-tools.md` на рабочем столе

По каждому инструменту: точное имя, описание, аргументы с типами и готовый блок `execute-mcp`
с примером. Выключенные серверы помечены отдельно.

### 🔒 Безопасность MCP (по итогам аудита)
- **В режиме whitelist MCP отключается целиком** (HTTP 403). Whitelist проверяет shell-команды,
  а `tools/call` — нет, поэтому оставлять его включённым означало бы дыру
- **Опасные инструменты требуют подтверждения даже при автопилоте**: `execute_*`, `run_code`,
  `write_*`, `delete_*`, `export_*` исполняют код или меняют проект
- **Токен больше не покидает `background.js`** — маскирование команд и вывода делает он,
  поэтому секрет не лежит в памяти страниц чата
- Таймаут вызова ограничен 10 минутами, ответ обрезается тем же лимитом, что и вывод
  shell-команды, ключи `__proto__` в аргументах отклоняются
- Очередь сообщений MCP ограничена по размеру: «сервер, который льёт в stdout»,
  больше не съедает память

### 📁 Личная настройка MCP
Серверы описываются в `server/mcp_servers.local.json` (в `.gitignore`), а поставляемый шаблон
`mcp_servers.json` остаётся выключенным — тем же приёмом, что и с `whitelist.txt`.
В `server.zip` личный конфиг не попадает, это проверяет `verify-artifacts.ps1`.

- Разбор JSON с понятными ошибками: мусор, отсутствие `server` или `tool`,

## ⚡ Палитра команд, свёрнутый вывод и журнал (v2.6.1)

Три вещи, которые экономят время каждый день.

### 1. Палитра команд — `Ctrl+Shift+E`

Рутинные команды («собери проект», «прогони тесты», «покажи `git status`») не нужно
выпрашивать у ИИ — их быстрее запустить самому. Нажми **`Ctrl+Shift+E`**
(на Mac — `Cmd+Shift+E`) прямо на странице чата.

В палитре:

| Действие | Клавиши |
|---|---|
| Выполнить (с подтверждением, если команда опасная) | `Enter` |
| Выполнить сразу | `Ctrl+Enter` |
| Вставить в чат как `execute`-блок | `Ctrl+I` |
| Закрепить / открепить команду (звёздочка) | `Ctrl+P` |
| Убрать команду из истории | `Del` |
| Закрыть | `Esc` |

- **История** — последние 30 запусков: команда, среда, код возврата, «5 мин назад».
  Повтор той же команды не дублируется, а поднимается наверх.
- **Закреплённые** идут первыми и хранятся между устройствами (`storage.sync`),
  так что рутинные сниппеты не надо набирать заново на каждом ПК.
- **Поиск** фильтрует по тексту и по среде (`python` находит запуск в Python);
  если совпадений нет, предлагается **новая команда** — можно ввести и запустить.
- **Среду** можно переключить прямо в строке (shell / powershell / python / node),
  значение запоминается для каждой команды.

Отключается в ⚙️ → **«Палитра команд и журнал»** → галочка «Палитра команд по Ctrl+Shift+E».

> 🔒 Секреты в журнал не пишутся. Если команда содержала `--token`, `Authorization: Bearer …`,
> `password=…` или токен самого сервера, в истории и в экспорте значение заменено на
> `«скрыто»`, а в палитре такая строка помечена чипом **«секрет скрыт»**. Нажать `Enter`
> на ней безопасно — команда не запустится, а текст подставится в поиск, чтобы дописать
> значение вручную.

### 2. Свёрнутый шумный вывод

Установка пакетов, дерево файлов, лог сборки — это экраны однотипных строк, а нужен
обычно только хвост. Такой вывод (40+ коротких однотипных строк) показывается
свёрнутым: виден верх блока с градиентом и кнопка
**«Вывод большой (300 строк) — показать полностью»**. Раскрыть можно и кликом по самому
блоку. Длинные «умные» строки (код, JSON, таблицы) не сворачиваются никогда.

Отключается в ⚙️ → **«Лимиты вывода»** → «Сворачивать длинные листинги в выводе».

### 3. Журнал выполнений + экспорт в markdown

⚙️ → **«Палитра команд и журнал»** → **«Экспорт в markdown»** выгружает
`ai-execute-journal.md`: таблица (время, среда, код возврата, команда) и полные тексты
команд в блоках `execute`. Хранятся только последние 30 записей; вывод команд и секреты
не сохраняются. Кнопка **«Очистить»** удаляет журнал.

Пригодится, чтобы вспомнить, что именно запускалось на этой машине, или приложить
выгрузку к разбору инцидента.

## 🤖 Автопилот (автовыполнение + автовставка + автоотправка)

В попапе расширения (клик по иконке ⚡):

1. **Автовыполнение новых execute-блоков** — команда запускается сама: расширение ждёт конца генерации ответа, показывает обратный отсчёт (по умолчанию 3 сек — окно отмены, кнопка «✋ Отмена авто») и выполняет.
2. **Автовставка вывода в поле ввода** — `[LOCAL EXEC RESULT]` сам появляется в поле чата.
3. **Автоотправка результата ИИ** — результат сам отправляется (нажимается кнопка Send, запасной вариант — Enter). Все три галочки вместе дают полный цикл как у Codex: ИИ пишет → выполняется → ИИ читает вывод → пишет дальше.

**Предохранители (включены всегда, отключить нельзя):**
- ⛔ Опасные команды (`rm -rf`, `sudo`, `format`, `curl|bash`…) **никогда** не выполняются автоматически — только вручную.
- 🛑 Лимит автозапусков на вкладку — настраивается в ⚙️ (по умолчанию **0 = без лимита**; поставь число, если боишься бесконечного цикла и жрущихся токенов).
- 🛑 Детектор зацикливания: одна и та же команда 3 раза подряд — автопилот останавливается.
- ⏭ Повторы не выполняются молча: команды из прошлых загрузок вкладки и блоки, уже бывшие на странице, пропускаются с запиской в чат — повтор только вручную кнопкой ▶.
- ⏱ Недогенерированные команды не запускаются: автозапуск ждёт, пока текст блока перестанет меняться.

> Лень искать попап? На самой панели под кодом есть кнопка «🤖 Включить авто» — включает полный автопилот в один клик.
>
> Начинай с первых двух галочек без автоотправки — посмотришь, как оно себя ведёт, потом включишь полный цикл.

## 🛡️ Безопасность (прочитай!)

- ✅ **Подтверждение каждого запуска** включено по умолчанию — ИИ ничего не выполнит без твоего клика. Не отключай без нужды.
- ⛔ На опасные паттерны (`rm -rf /`, `sudo`, `format`, `curl|bash`, `Remove-Item -Recurse`, `Format-Volume`, `rmdir /s`, `git clean -fdx`…) модалка покажет **красное предупреждение**, а автопилот такие команды не выполнит. С v2.6.1 проверка не обходится кавычками (`rm -rf "/"` ловится так же, как `rm -rf /`).
- 🧱 UI панелей и окна подтверждения живёт в **закрытом shadow DOM**, а запуск требует настоящего действия пользователя (`isTrusted`) — скрипт со страницы чата не может «нажать» ▶ или подтвердить запуск за тебя.
- 🔒 Сервер слушает только `127.0.0.1`, вывод обрезается (1 МБ), есть таймаут (по умолчанию 30 сек).
- 🧱 Проверка `Host`/`Origin`: запросы с чужим Host (DNS-rebinding) или Origin (чужой сайт) отклоняются с `403`. Разрешены только локальные и `chrome-extension://`; CORS-заголовок отдаёт проверенный Origin, а не `*`.
- 🔑 Токен доступа хранится только локально (`storage.local`) и не синхронизируется в облако вендора; в файл лога и в экспорт настроек он не попадает.
- 📏 Лимиты вывода (настраиваются, 0 = без лимита): сервер — до 1 МБ (`python server.py --max-output 0`), вставка в чат — до 32000 символов (поле в настройках ⚙️). При обрезке в результате есть пометка с лимитом.
- 🙅 Не давай ИИ доступ, когда отходишь от ПК; не подтверждай команды, которых не понимаешь.

> 🩺 Странный/пустой вывод? Смотри [TROUBLESHOOTING.md](TROUBLESHOOTING.md) — известные проблемы, настоящие причины и обходы.
- 💡 Для экспериментов можно запускать сервер из пустой папки или под отдельным пользователем.

## 🔧 Настройки

Полная страница настроек — **все** параметры в одном месте. Открыть можно тремя способами:
- кнопка **«⚙️ Все настройки»** в попапе расширения;
- правый клик по иконке ⚡ → **Параметры**;
- `chrome://extensions` → **Сведения** → **Параметры расширения**.

Разделы: 🖥 Сервер · 🛡️ Подтверждения · 🤖 Автопилот · 🔀 Среды выполнения · 🔍 Поиск блоков · ⚡ Палитра и журнал · 📏 Лимиты · 🔔 Уведомления.

Быстрые параметры (сервер, подтверждение, автопилот) продублированы в попапе — для доступа в один клик.

### 🎨 Интерфейс

Единая дизайн-система (`ax-ui.css`) с токенами цвета, типографики, отступов и теней; светлая и тёмная темы, авто-режим по системной.

**Кастомизация оформления** — в разделе «Внешний вид» есть кнопка «Все настройки», которая раскрывает четыре независимых переключателя (экспериментально):

| Настройка | Значения | Что меняет |
|---|---|---|
| Палитра | Индиго, Океан, Изумруд, Закат | акцентный цвет; поверхности и текст остаются за темой, поэтому палитра читается и в светлой, и в тёмной |
| Скругление | Плиточное, Острое, Обычное, Круглое, Таблетка | токены `--ax-r-*`: кнопки, поля, карточки, чипы и тосты |
| Стиль кнопок | Мягкие, Заливка, Контур, Плоские, Плитка | фон, рамку и скругление `.ax-btn` |
| Плотность | Компактно, Обычно, Просторно | кегль и вертикальные отступы |

Палитра не трогает поверхности намеренно: иначе половина палитр оказывалась бы нечитаемой в одной из тем. У каждой палитры поэтому два набора акцента — светлый и тёмный.

Механика: настройки лежат в `sync`-хранилище, а на `<html>` (страница настроек, попап) или на хосте панели (модалки, палитра команд) ставятся атрибуты `data-ax-palette`, `data-ax-radius`, `data-ax-btn`, `data-ax-density`. Значения прогоняются по белому списку — произвольная строка из импортированного бэкапа в разметку не попадёт. Внутри shadow root селекторы продублированы как `:host([...])`: обычный селектор через границу тени не проходит, и без этого оформление не применилось бы к панели.

- **Страница настроек** — навигация по разделам с подсветкой текущего, поиск по настройкам (`/` — фокус, `Esc` — сброс), сохранение по `Ctrl+S`, липкая панель действий, индикатор несохранённых изменений. Тема и оформление применяются до первой отрисовки, поэтому нет «мигания» светлым.
- **Панель под кодом** — иконки вместо эмодзи, читаемая шапка (бейдж EXECUTE/EXECUTE?, среда, действия), предпросмотр команды с подсказкой «ещё N стр.», цветной индикатор статуса, отдельный блок вывода, кнопки «В чат» и «Копировать». Размер панели и тема настраиваются.
- **Попап** — статус сервера с цветным индикатором, свитчи-переключатели (клик по всей строке), автопилот с иерархией «основное → дочерние».
- **Доступность** — видимый фокус (`:focus-visible`), управление предпросмотром с клавиатуры, `prefers-reduced-motion`.

Посмотреть интерфейс без установки расширения:

```

1. **ax-detector.js** — чистые функции без побочек (сниффер языка, детекция
   блоков, опасные паттерны, маскирование секретов). UMD: работает и в браузере,
   и в Node — поэтому покрыт юнит-тестами.
2. **ax-core.js** — namespace `AX`: настройки, безопасная отправка сообщений,
   работа с полем ввода чата, форматирование результата, история, журнал команд
   и память среды.
3. **ax-view.js** — всё про `view`: вставка картинки в чат (file-input → paste →
   execCommand → clipboard) и превью под панелью.
4. **ax-panel.js** — панель под блоком, модалка подтверждения, очередь
   автозапусков, логика автопилота и свёртывание шумного вывода.
5. **ax-palette.js** — палитра команд по `Ctrl+Shift+E`: история, закреплённые,
   поиск, выбор среды, запуск и вставка `execute`-блока в чат.
6. **content.js** — точка входа: scan, MutationObserver, диагностика, бейдж.

> Порядок важен и продублирован в `background.js` (`AX_CONTENT_FILES`) для
> докачки скриптов в уже открытые вкладки.
